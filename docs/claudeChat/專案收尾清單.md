- `README.md` 還是 Flutter 預設樣板（"A new Flutter project."），`pubspec.yaml` 的 `description` 也是

- 如果之後要當作求職作品，README 是別人第一個看到的地方

### B-4. App 識別與正式版安裝（如果要長期裝在小孩用的手機上）

- `applicationId`／`namespace` 還是 `com.example.elevator`
- 桌面上顯示的名稱是 `android:label="elevator"`，而 `MaterialApp.title` 是 `Kid's Elevator`，兩者不一致
- `release` 目前用 debug 簽章（`signingConfig = signingConfigs.debug`），`build/` 裡也只有 `app-debug.apk`
- 用 `flutter build apk --release` 裝到實機：release 版比 debug 版流暢，右上角也不會有 DEBUG 標籤
- 如果只是自己裝來用，`applicationId` 可以不改；改了等於一個新 App，舊的要另外移除

### B-5. 版本控制與備份

- 確認沒有未 commit 的變動，推到 GitLab
- 打一個 tag（例如 `v1.0.0`，和 `pubspec.yaml` 的 `version: 1.0.0+1` 對應），之後回頭補測試或開新專案時有明確的收尾點
- 依照既有做法，把 Project 文件下載到本機 `docs/` 做最後一次備份
