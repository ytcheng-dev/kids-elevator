# 文件與程式碼整理待辦清單

本清單記錄針對文件與程式碼整理提出的建議事項（來源：`claude/專案體質檢視報告.md` 與專案收尾時的檢查）。已完成的項目直接移除，不留紀錄；只保留「決定不處理（附原因）」與「尚未處理」兩類。任何文件或程式碼的實際調整，都要先在該次對話中取得使用者同意才進行。

---

## 一、決定不處理的事項

| 事項 | 決定 | 原因 |
|---|---|---|
| 動物模式點擊目前所在樓層時沒有任何 UI 反應 | 維持現狀，不修改行為 | 刻意設計，不是缺陷；行為已寫入 `設計主軸.md` 動物模式第 5 點 |
| `openDoor()` 內層重複的門狀態判斷（外層已限定 `doorStatus == closed`，內層 `!= opening && != open` 必定成立） | 維持現狀，外層與內層的條件都保留 | 閱讀時比較容易理解：內層條件直接寫出「哪些門狀態會觸發開門」，不需要回頭看外層才知道 |
| `LayoutCss` 未使用的 getter（`h2`～`h4`、`h6`、`m3`、`mt1`～`mt3`、`mb2`、`pt1`～`pt3`、`pb1`～`pb3`） | 維持現狀，不移除 | 沒用到就沒用到，作為完整的樣式工具組保留（也因此拉低 `layout_css.dart` 的測試覆蓋率） |
| release 版使用 debug 簽章（`build.gradle` 的 `signingConfig = signingConfigs.debug`），沒有建立正式的簽章金鑰 | 維持現狀 | 不上架 Google Play、App 不儲存任何資料；正式簽章的用途（上架、跨電腦覆蓋更新）對這個專案都不需要，真的要上架時再建立 |
| `ios/`、`macos/`、`linux/` 設定檔裡的識別碼仍是 `com.example.elevator`（Android 已改為 `com.ytc.kidselevator`） | 維持現狀 | `設計主軸.md` 明確只做 Android，其他平台的設定不使用 |
| 建置時警告 Gradle（8.14）、Android Gradle Plugin（8.11.1）、Kotlin（2.2.20）的版本「很快就不支援」 | 維持現狀，不升級 | 專案已收尾，目前仍能正常建置；下個專案再決定怎麼處理 |
| 建置時 Kotlin 增量編譯的快取寫不進去（pub cache 在 C 槽、專案在 D 槽，Windows 上算不出跨磁碟的相對路徑），會印出大量錯誤並改為完整重新編譯 | 維持現狀，不處理 | 專案已收尾，建置仍能成功；下個專案把 pub cache 改放到 D 槽 |
| claude.ai Project 內部路徑不一致（部分文件在根目錄、部分在 `claude/` 子目錄） | 維持現狀，不收斂 | 不影響使用 |
| Project 與本機 `docs/` 的同步節奏 | 不設固定節奏，Claude 不需要主動提醒 | Project 是正本；本機 `docs/` 只是單向下載、推到 GitLab 保存的完整備份，本機不修改、不回寫，隨興下載即可 |
