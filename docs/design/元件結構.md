# 元件結構

本文件涵蓋 `widgets/` 這一層——可重用的純顯示元件，與 `資料結構.md`（`models/` + `styles/` + `constants/` + `interfaces/`，純資料/邏輯層）、`畫面結構.md`（`screens/`，畫面組裝、業務邏輯、`Navigator` 導覽）互補（Phase 14 從原本同時涵蓋 `widgets/`＋`screens/` 兩層的單一文件拆分而來，`screens/` 相關內容已搬到 `畫面結構.md`）。格式比照 `資料結構.md`，分兩個區域：

- **一、元件速查**：開發中需要立即查詢的資訊——class 名稱、檔案位置、建構子參數、用途。只看目前的正確狀態，不含歷史沿革。
- **二、設計考量與取捨**：需要判斷「為什麼這樣拆」或評估是否要調整某個元件時才需要查閱。同一個決定如果經過反覆調整，只保留「最後被捨棄的做法＋捨棄原因」與「最終定案＋定案理由」。

## 一、元件速查

### `widgets/` 共用元件（不分模式，位於最外層）

**ArrowIcon**（`widgets/arrow_icon.dart`，`StatelessWidget`）
依 `directionIcon: ScreenIcon`（final）決定顯示哪個方向的箭頭圖示（`size: 96`），回傳 `FittedBox(child: Icon(...))`：`up`／`down` 為 `Icons.arrow_upward`／`Icons.arrow_downward`（`LayoutCss.primary`），`left`／`right` 為 `Icons.chevron_left`／`Icons.chevron_right`（`LayoutCss.secondary`）。

**BackLeading**（`widgets/back_leading.dart`，`StatelessWidget`）
返回／回首頁用的按鈕，包一個 `IconButton`，固定使用 `Icons.home` 圖示，樣式為 `LayoutCss.primary7`（前景）／`LayoutCss.secondary0`（背景）、圓形、`elevation: 6`。參數：`onPressed: VoidCallback?`（對外開放，呼叫端決定要導去哪裡；`PanelPage`（透過 `_getHomeButton`）與 `AnimalPage` 都用它搭配 `Navigator.pop` 返回首頁）。內部的 `onPressed` 固定包一層 `() { onPressed?.call(); }`，所以就算沒有傳入 callback，按鈕也不會呈現停用狀態。

**FloorTile**（`widgets/floor_tile.dart`，`StatefulWidget`）
樓層按鈕，**面板模式與動物模式共用同一份實作**。參數：`floorButton: FloorButton`（final）＋ `onTap: VoidCallback?`。按壓中的視覺回饋（`_isPressed`）是元件自己的 local state，透過內部 `GestureDetector` 的 `onTapDown`/`onTapUp`/`onTapCancel` 直接觸發自己的 `setState()` 管理。依 `floorButton.isTarget` 決定外觀：

| | `isTarget == false` | `isTarget == true` |
|---|---|---|
| 背景 | `LayoutCss.secondary0` | `LayoutCss.secondary2` |
| 邊框／陰影顏色 | `LayoutCss.neutral2` | `LayoutCss.secondary5` |
| 文字顏色 | `LayoutCss.text1` | `LayoutCss.secondary5` |
| 陰影偏移 | 未按下 `(0, 5)`、按下 `(0, 1)`，做出按壓凹陷的視覺回饋 | 固定 `(0, 5)`，按壓時不變 |

**VolumeButton**（`widgets/volume_button.dart`，`StatelessWidget`）
音效／語音開關按鈕。參數：`volumeType: VolumeType`（final）、`isAllow: bool`（final）、`onPressed: VoidCallback?`。依 `volumeType` 決定使用哪一組圖示（`sfx`：`Icons.volume_up`/`Icons.volume_off`；`voice`：`Icons.music_note`/`Icons.music_off`），再依 `isAllow` 決定顯示開或關的圖示，回傳 `IconButton(icon: Icon(icon), onPressed: onPressed)`，樣式為 `LayoutCss.primary7`（前景）／`LayoutCss.surface`（背景）、圓形、`elevation: 6`。

---

### `widgets/panel_page/`（面板模式專用元件）

**DoorButton**（`widgets/panel_page/door_button.dart`，`StatefulWidget`）
開/關門按鈕。參數：`actionButton: ActionButton`（final）＋ 3 個 `VoidCallback?`：`onTap`、`onLongPressStart`、`onLongPressEnd`。圖示由元件依 `actionButton.btnType` 自己決定（開門 `Icons.unfold_more_outlined`、關門 `Icons.unfold_less_outlined`，外層 `RotatedBox(quarterTurns: 1)` 轉成左右方向），`ActionButton` 本身不存圖示。按壓中的視覺回饋（`_isPressed`）是元件自己的 local state，由內部 `Listener` 的 `onPointerDown`/`onPointerUp`/`onPointerCancel` 直接觸發自己的 `setState()` 管理，不對外暴露這三個事件；按下時背景（`secondary0` → `secondary2`）、邊框與圖示顏色（→ `secondary5`）、陰影偏移（`(0, 5)` → `(0, 1)`）都會改變。內部仍用 `Listener` + 手勢偵測（`GestureDetector`）巢狀包裝，`onTap`／`onLongPressStart`／`onLongPressEnd` 透過 `widget.xxx` 呼叫外部傳入的 callback。呼叫端（`_getDoorButton`）只對開門按鈕傳入長按 callback，關門按鈕傳 `null`。

**DirectionIcon（面板模式版）**（`widgets/panel_page/direction_icon.dart`，`StatelessWidget`）
樓層顯示區的方向箭頭（含滑動動畫）。參數：`elevator: Elevator`（final）＋ `animateOffset: AnimateOffset`（final）。依 `elevator.direction`／`elevator.doorStatus` 決定要用 `animateOffset` 的哪個 `Animation<Offset>` 包在 `SlideTransition` 裡，並顯示對應的 `ArrowIcon`：`direction == idle` 時再依 `doorStatus` 是 `opening`／`closing` 決定顯示左右箭頭滑開／滑合的動畫，其餘門狀態（`closed`／`open`）用 `Spacer()` 佔位；`up`／`down` 則顯示對應方向箭頭。

**FloorDisplay**（`widgets/panel_page/floor_display.dart`，`StatelessWidget`）
樓層數字顯示區整體。參數：`elevator: Elevator`、`animateOffset: AnimateOffset`、`floorText: String`。組合（面板模式版）`DirectionIcon` ＋ 樓層文字（`Expanded` + `FittedBox` + `Text`，`LayoutCss.secondary`、`LayoutCss.h1`），外框為 `LayoutCss.neutral9` 底色、`LayoutCss.neutral8` 邊框。

---

### `widgets/animal_page/`（動物模式專用元件）

**DirectionIcon（動物模式版）**（`widgets/animal_page/direction_icon.dart`，`StatelessWidget`）
樓層顯示區的方向箭頭（含滑動動畫），動物模式簡化版。參數：`direction: Direction`（final）＋ `animateOffset: AnimateOffset`（final）。動物模式沒有開關門狀態，只依 `direction` 決定顯示 up/down 哪個 `ArrowIcon`（用對應的 `upFloorOffset`／`downFloorOffset` 包在 `SlideTransition`），`idle` 時用 `Spacer()` 佔位，不需要像面板模式版處理 `doorStatus` 的開關門箭頭動畫。

**QuestionButton**（`widgets/animal_page/question_button.dart`，`StatefulWidget`）
動物模式的提問按鈕，顯示動物大頭貼，供玩家點擊重播題目語音。參數：`animalImg: String`（final）、`isShining: bool`（預設 `false`，是否播放「說話中」提示動畫）、`onTap: VoidCallback?`。按壓中的視覺回饋（`_isPressed`）是自己的 local state，由 `GestureDetector` 的 `onTapDown`/`onTapUp`/`onTapCancel` 管理，決定外層陰影偏移量（陰影顏色固定用 `LayoutCss.neutral7`）。另外用一個 500ms 的 `AnimationController` 驅動 `ColorTween`（`LayoutCss.secondary` → `LayoutCss.secondary1`）：`initState()` 時若 `isShining` 為 `true` 就直接開始，之後在 `didUpdateWidget` 比對新舊 `isShining`，決定 `repeat(reverse: true)` 或 `stop()`＋`reset()`，同步套用在大頭貼外框（`key: ValueKey('border-container')`）與右下角小音量圖示（`key: ValueKey('icon-container')`）上，做出「說話中」的閃爍提示。

## 二、設計考量與取捨

**三層架構：`models/` / `widgets/` / `screens/`（另加獨立的 `styles/`）**
`models/` 是純資料／邏輯物件；`widgets/` 是可重用的顯示元件（不含業務邏輯）；`screens/` 負責把 `widgets/` 組裝成完整畫面、並持有業務邏輯與可變狀態，細節見 `畫面結構.md`。`styles/` 特意獨立於 `models/` 之外，避免跟 Flutter 自己的 `Theme`/`ThemeData` 概念語意衝突。

**為什麼把「回傳 Widget 的方法」抽成獨立的 `StatelessWidget` class，而不是留在畫面的 State 裡當方法**
獨立成 class 可以標記 `const`（減少不必要的重建）、在 DevTools 的 Widget Tree 中會是獨立節點方便除錯定位、建構子參數是明確的依賴注入，不像方法用閉包隱式讀取外層 state 欄位。

**抽取優先順序，依複雜度分級**
第一級：純粹「輸入→輸出」、不需要 callback（例：`ArrowIcon`）最先抽。第二級：需要透過建構子傳入 callback（例：`DoorButton`、`FloorTile`、`VolumeButton`）。第三級：需要共用 `AnimationController`／動畫狀態（例：`DirectionIcon`、`FloorDisplay`、`QuestionButton`）最後處理，且需要額外設計「Controller 留在哪裡」（留在畫面的 State，詳見 `畫面結構.md`）。

**`DoorButton` 對外只用不帶參數的 `VoidCallback?`，不直接暴露 `Listener`/`GestureDetector` 原生的事件型別**
檢查過實際呼叫端，從未用到事件參數本身；暴露原始事件型別只是徒增外部依賴、沒有實際使用需求。內部用 lambda 把原生事件包一層再轉呼叫 `VoidCallback?`。

**`DirectionIcon`（面板模式版）為什麼傳入整個 `Elevator` 物件，而不是只傳 `Direction`／`DoorStatus` 兩個欄位**
明知道傳整個物件耦合度較鬆，但考量呼叫端比較方便、不用逐一挑欄位，故意接受這個取捨。

**命名規則：避免 `models/` 跟 `widgets/` 撞名**
model 用領域概念命名（`FloorButton`、`ActionButton`），widget 用 UI／視覺角色命名，字彙盡量貼近 Flutter 自己既有 widget 的命名習慣（`Tile`、`Card`、`Chip`、`Bar`、`Panel`、`Icon`、`Button`、`View`）。例如資料是 `FloorButton`，畫面元件是 `FloorTile`；資料是 `ActionButton`，畫面元件是 `DoorButton`；純顯示用的圖示邏輯是 `ArrowIcon`。真的無法避免撞名時，退而求其次用 `import '...' as prefix;` 做區隔。

**`ActionButton.isPressed` 為什麼改成 `DoorButton` 自己管理的 local state**
按壓中的視覺回饋只有 `DoorButton` 自己在乎、不影響任何業務邏輯（`openDoor()`/`closeDoor()`/`doorButtonOnTap()` 等都不會讀取這個值），屬於 Flutter 官方分類中的 ephemeral state，適合留在對應的 `StatefulWidget` 自己的 `State` 裡管理，不需要上提到畫面的 State。原本放在 `ActionButton` model、透過畫面 State 的 `setDoorButtonPressed()` 更新的作法，會讓每次按壓/放開都觸發最外層 `State` 的 `build()`（雖然這個 app 規模小、效能差異無感，但重繪範圍不必要地擴大）；改成 local state 後，`DoorButton` 元件本身更完整，未來若被其他畫面重用也不需要外部記得處理這個狀態。因此 `ActionButton` 移除 `isPressed` 欄位、回歸純資料，`DoorButton` 建構子也拿掉了原本對外暴露的 `onPointerDown`/`onPointerUp`/`onPointerCancel` 三個參數。

**Phase 17/18 動物模式上線後，`widgets/` 為什麼不是整層一致拆成 `panel_page/`、`animal_page/` 兩個子目錄**
只有顯示邏輯真的因模式而異的元件（`DirectionIcon`）才各自拆一份、歸類到對應子目錄；`DoorButton`、`FloorDisplay` 目前只有面板模式在用，直接歸到 `panel_page/`；`QuestionButton` 只有動物模式在用，歸到 `animal_page/`；`ArrowIcon`、`VolumeButton`、`BackLeading`、`FloorTile` 兩個模式共用或還沒有模式差異，留在 `widgets/` 最外層，不預先幫還沒分裂的元件建立子目錄容身。

**`FloorTile` 為什麼兩個模式共用同一份實作，而不像 `DirectionIcon` 一樣各自一份**
刻意決策：為了讓面板模式與動物模式的樓層按鈕維持一致的視覺風格，選擇共用同一份 `StatefulWidget` 實作，而不是依模式各自客製化。

**`DirectionIcon` 為什麼兩個模式各自維護一份，而不是共用**
兩個模式的顯示邏輯本質不同：面板模式需要處理開關門狀態（`doorStatus`）衍生的左右箭頭滑開／滑合動畫，動物模式沒有門的概念，只需要處理上下方向兩種箭頭。硬要共用會讓其中一個模式帶著大量用不到的參數與分支，因此刻意拆開，各自對應各自的資料模型（面板模式吃 `Elevator`，動物模式吃 `Direction` 這個欄位本身）。
